==================================================
3. BUSINESS LOGIC BOUNDARY (WAJIB DIPATUHI)
==================================================

Flutter BOLEH:
- Menampilkan hazard, severity, confidence, route, cost breakdown
  apa adanya dari response API.
- Melakukan transformasi presentasi ringan (contoh: format tanggal,
  hitung jarak haversine untuk kartu destinasi).
- Menangani UI state: loading, empty, error, submitting, disabled, dll.
- Melakukan navigasi, form input, capture foto, polling, render peta/marker.

Flutter TIDAK BOLEH menghitung:
- risk score, hazard_penalty, uncertainty_penalty, total_cost
- shortest path / route safety
- klasifikasi hazard atau ekstraksi AI (foto/teks/voice)
- route recalculation logic

Jika ragu apakah sesuatu termasuk boundary Flutter atau backend,
STOP dan tanyakan — jangan berasumsi.

==================================================
4. URUTAN IMPLEMENTASI (PHASE 1–7)
==================================================

### Phase 1 — Foundation
- Repository layer + Riverpod controllers/notifiers per fitur.
- Polling service reusable, interval default 20 detik (via .env).
- Disclaimer widget (tampil sekali per launch, state in-memory).
- Halaman Settings/About (ui-ux §8.13).
- Standarisasi pola loading/error/empty state di seluruh app.

### Phase 2 — Dynamic Safety Map
Prasyarat: Phase 1 selesai.
- Integrasi `GET /hazards?status=&bbox=&updated_since=` ke map_screen.dart.
- Marker hazard berwarna sesuai severity, HUD count dinamis.
- Bottom sheet dinamis, manual refresh + delta polling.

### Phase 3 — Destination Selection
Prasyarat: Phase 2 selesai.
- Integrasi `GET /destinations` dan `POST /routes`.
- Kartu destinasi: nama, tipe, jarak haversine (tanpa ETA).

### Phase 4 — Route Visualization (representasi non-spasial, GAP-01)
Prasyarat: Phase 3 selesai.
- Cost summary strip (base + hazard_penalty + uncertainty_penalty = total).
- List segmen (road_segment_id + cost) sebagai representasi sementara.
- Deteksi recalculation (superseded_by_route_id) + banner,
  polling `GET /routes/active`.

### Phase 5 — Hazard Reporting
Prasyarat: Phase 1 (boleh paralel dengan Phase 2–4).
- Photo: capture → preview + lokasi otomatis → submit multipart →
  AI review panel (type/severity/confidence/road_impact/evidence) →
  confirm/reject.
- Text: form → submit langsung → hasil read-only setelah sukses
  (sesuai CONFLICT-01).
- Quick: grid 6 kategori → submit {category, lat, lng}.
- Handle: permission kamera ditolak, upload progress, AI timeout,
  validasi input kosong, double-submit guard.
- Tile Voice DIHAPUS dari Report Selector (sesuai CONFLICT-02).

### Phase 6 — Hazard Review
Prasyarat: Phase 2 selesai.
- Detail sheet dari tap pin/list: severity, confidence, status,
  source, evidence, conflicting_with[] — dibuat dari nol (belum ada).
- List screen hazard.

### Phase 7 — Emergency Simulation
Prasyarat: Phase 4 selesai.
- Integrasi `GET /simulation/scenarios`,
  `POST /simulation/scenarios/{id}/run`,
  `GET /simulation/runs/{run_id}`.
- Progress indicator, panel perbandingan baseline vs risk-aware + cost.
